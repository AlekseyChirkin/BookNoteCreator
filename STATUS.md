## 2. Текущее поведение (проверено)

### 2.1 Запуск (dev и portable)
- **Dev**: `python web_book_parser.py` — сервер на :5000, браузер открывается.
- **Portable**: `dist\BookNoteCreator\BookNoteCreator.exe` — сервер стартует, страница отдаётся (HTTP 200), иконка base64 на месте, CSS-тема отдаётся.
- **Повторный запуск**: если порт занят — второй exe открывает браузер и сразу выходит (не падает).

### 2.2 Парсинг — **СЛОМАН (главная проблема)**
- **author.today** — сайт за **Cloudflare challenge** («Just a moment…» / «Один момент…»).
  - Playwright (headless) получает защитную страницу, НЕ контент книги.
  - `playwright-stealth` (новый API Stealth) — не помог.
  - Headful (видимый браузер) — также challenge; процесс держал окно и был прерван.
- **litres.ru** — при `requests`-парсинге отдаёт **404/антибот** (проверено на реальных URL); парсер возвращает пустой словарь без `error` → UI показывает «данные загружены» с пустыми полями («Автор: Не доступно», «Тип: Книга»).
- **Пустые данные без error** — это отдельный баг фронта: если все поля пустые, всё равно ставится `previewReady = true` и кнопка Save разблокируется. Нужно валидировать на фронте.

## 3. Проблемы (отчёты пользователя)

| # | Проблема | Статус |
|---|---|---|
| 1 | Кнопка всегда неактивна | Причина #2 (парсер не достаёт данные) + невалидный preview |
| 2 | «Данные загружены», поля пустые | Подтверждено: парсер возвращает пустоту; Cloudflare/404 на сайтах |
| 3 | Бек «падает» при первом запуске | Скорее всего: single-instance лог в старом билде (порт занят → просто открывался бруз) + стоп-лог из watchdog; **нужна перепроверка на чистом билде** |
| 4 | Бек «виснет» при парсинге | Playwright застревает на Cloudflare (таймаут goto 60 c), запрос /parse не возвращается → у пользователя ощущение «повис» |
| 5 | Бек закрывается при повторных запусках | Ожидаемое поведение single-instance + watchdog, но в UX не понятно. Возможно, стоит логировать в stdout. |

## 4. Предположения / гипотезы

### 4.1 Главная: парсинг против анти-бот защиты
- author.today и litres.ru используют **Cloudflare/анти-бот**, который детектит headless Chromium.
- Гипотеза: нужен **настоящий Chromium в headful режиме** (видимое окно) — как fallback, либо:
  - `--disable-blink-features=AutomationControlled` + обои через **`launch_persistent_context`** с профилем (реальнее по fingerprint).
  - **waited не 2 сек, а до фактического появления контента**: `page.wait_for_selector('.book-title')` с тайм-аутом 30–60 c.
- Лучший вариант: не полагаться на авто-парсинг в первым, а **показать пользователю окно Chromium headful** на время парсинга author.today — тогда Cloudflare почти наверняка пропустит (ручная капча = действия пользователя).

### 4.2 «Пустые данные без ошибки»
- В `web_book_parser.py` `/parse` не проверяет, что `title`/`annotation` реально заполнены. Нужно: если `not book_info.get('title')` → `400 {'error': 'не удалось извлечь данные'}`.
- На фронте: если `data.title` пустой → показывать ошибку, а не «данные загружены».

### 4.3 Портабельная сборка
- PyInstaller 6.x: `sys._MEIPASS` указывает на `_internal`. Мы уже это учли в `app_paths.configure_playwright()`.
- pinned playwright version + browsers должны совпадать с сборкой (вшитые `_internal/playwright-browsers`).
